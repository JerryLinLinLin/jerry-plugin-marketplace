# Guest interaction

Open a running VM using `hyperv_console` with `session=default` (Basic), unless the task asks for Enhanced or needs its clipboard/display features. Inspect returned `sessionMode` and fallback note. Each MCP process owns its consoles; close them when finished. An Enhanced connection may require the guest's RDP sign-in. Opening it does not change a saved VM preference.

Basic screenshots come from Hyper-V's guest framebuffer and work in the background. Use the returned native pixel coordinates for click/move/scroll. Keyboard goes to the VM's synthetic keyboard; Enhanced uses its RDP input sink. Neither sends global host keystrokes. `type` sends text, `key` sends chords such as `WIN+R`, `CTRL+A`, `CTRL+ALT+DELETE`; click supports left/right/double. For drag: button_down, move, button_up, and release in recovery even if an intermediate operation fails. Scroll deltas use 120 units per notch.

Enhanced screenshots capture its actual remote desktop window and must fail if that window is minimized, off-screen or obscured. Bring the specific window forward with the user's cooperation if needed; do not report another host window as the VM. The inline PNG is the observation; do not load an unrelated old screenshot. After navigation/input, capture again before choosing new coordinates.

`login` only enters the stored password into the currently focused guest sign-in password field and presses Enter. Inspect the sign-in screen first and select the intended guest user. Never call it at an unknown focus. This does not configure automatic login. Clipboard read/write affects the host clipboard redirected into Enhanced sessions; it is not isolated per VM. Prefer `type` or file copy when shared clipboard is unnecessary.

PowerShell Direct works without network/RDP but does not enter an interactive desktop. Use `guest_run` for shell work and `copy` for bidirectional files/folders. Paths are absolute, `..` is rejected, and guest→host copies cannot target Windows or Program Files. Check exitCode/timedOut/truncated; process timeout is not rollback. `guest_process` accepts an argument array without shell concatenation.

For semantic UI, call `guest_setup` once, then `ui` with `status`, `list-windows`, `inspect` or `search`. Use live element identities and supported `invoke`, `set-value`, `focus` etc. Microsoft's winapp CLI is installed from a release with a verified published digest. The bridge runs it in the signed-in guest session through a task; an unlocked interactive sign-in is required in either console mode. `elevated=true` is for elevated guest apps; ordinary desktop and AppContainer apps normally need the default token. Multiple interactive guest sessions require verifying the window/session selected. Errors such as locked desktop, missing session or stale element need a fresh observation, not repeated clicks.
